## 1. Error 500 de Agenda (reproducido y corregido)

**Causa:** `views/agenda/show.ejs` usaba `duracionTexto(...)`, una función definida solo dentro de `views/agenda/index.ejs`. Al abrir una tarea desde el calendario, EJS lanzaba `ReferenceError: duracionTexto is not defined` y respondía 500.

**Reproducción:** crear una tarea con solo título y hora (`POST /agenda`), luego abrir `GET /agenda/:id`.

**Fix:**
- `utils/dates.js`: nueva función `duracionTexto`.
- `app.js`: expuesta como helper global de vistas.
- `agendaController.js` e `index.ejs`: eliminadas las copias locales.

**Verificado:** `GET /agenda/:id` responde 200.

## 3. MikroTik atómico

- **VLAN** (`vlanService`): cada paso tiene comando de reversión. Si falla la dirección, se borra la VLAN; si falla una actualización, se restaura nombre, dirección y estado.
- **Firewall y EOIP**: el registro se guarda solo si el router acepta el cambio. Si falla, se devuelve 502 y no queda registro.
- **DHCP** (`dhcpServerService`): se lee el estado del router antes de crear, y si un paso falla se eliminan solo los objetos que no existían antes (pool, red, servidor, dirección).
- **Habilitar/inhabilitar**: ya no se guarda el cambio si el router lo rechaza.

## 15. Restauración real de respaldos (CHR clon)

Se copió el VHD y se probó sobre una VM aparte, nunca sobre el CHR de trabajo.

**Preparación:** copia del VHD, `/system reset-configuration no-defaults=no keep-users=yes`, arranque en puertos 18728/12222.

**Respaldo `.rsc`:**
- En un equipo con la misma configuración, el import falla por objetos duplicados (VLANs, perfiles) y se detiene.
- En un equipo limpio, con dos ajustes, importó **sin errores**:
  - se omitió `/ip dhcp-client add interface=ether1` porque el equipo ya tenía DHCP;
  - se omitió `/ip service set api-ssl certificate=ct-tls` porque los certificados no viajan en el export.
- Resultado: 2 VLANs, 5 perfiles PPP, 1 cola, 1 dirección, 3 reglas de firewall, 1 address-list, 3 rutas, 2 secretos PPP y la nota del sistema restaurados.

**Respaldo binario:**
- Se cargó, el equipo se reinició y volvió con la configuración del respaldo: nota restaurada, 2 VLANs, 3 reglas de firewall y 1 secreto PPP.

**Conclusión:** ambos formatos restauran. Después de un `.rsc` hay que volver a crear certificados y revisar el DHCP; el binario conserva secretos y certificados, pero reinicia el equipo.

## 21. Permisos granulares de la ficha del cliente

Se creó el grupo **Clientes** con cuatro nodos:

| Nodo | Alcance |
|---|---|
| `clientes.datos` | Ver/editar datos generales, portal y eliminar cliente sin historial |
| `clientes.servicio` | Crear/editar servicio, plan, router, pool, IP, PPPoE y eliminar servicio |
| `clientes.cortes` | Cortar/restaurar por MOROSOS y desactivar/activar PPPoE |
| `clientes.facturacion` | Ver la pestaña Facturación del cliente |

Comportamiento:

- Las pestañas se muestran solo si el usuario tiene el nodo correspondiente.
- El controlador redirige a “Datos generales” si se intenta abrir una pestaña no permitida.
- `ventas.instalar` queda solo para completar/instalar una venta; ya no gobierna la ficha del cliente.
- `general.clientes` sigue siendo la base para listar y abrir la ficha.
- `finanzas.facturacion` controla “Verificar facturación”.
- Migración aplicada a los usuarios existentes y seed actualizado:
  - técnico: datos, servicio y cortes
  - ventas: datos y facturación
  - soporte: datos
  - finanzas: facturación

Verificado: técnico ve Servicio y Cortes; ventas y finanzas solo Facturación; soporte solo consulta; un usuario sin `clientes.cortes` recibe 403 al intentar cortar.
